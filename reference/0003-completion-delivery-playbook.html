Reference 0003

Completion delivery playbook

An outbox state machine for waking one originating Codex thread without losing or duplicating the callback.

Durable identity

  • Server: resolved CODEX_HOME and control socket.
  • Destination: originating threadId.
  • Completion: stable identity derived from delegation and worker-turn identity.
  • Message: one stable clientUserMessageId reused during reconciliation.

State machine

PendingPersist before network I/O.
→
RoutingResume thread and inspect active state.
→
UnknownTimeout means reconcile, never guess.
→
AcceptedStore turn or queue submission ID.
→
ConsumedObserve the resulting user turn.

Routing rule

Idle

Use turn/start with the stable client message ID.

Active + queue

Use experimental thread/queue/add; store its submission ID.

Active, no queue

Keep the outbox item pending until turn/completed, then start it.

Reconciliation rule

  1. Reconnect and initialize against the same server.
  2. Resume the destination thread.
  3. Search queued submissions and user-message history for the stable client message ID.
  4. If found, mark accepted and do not resend.
  5. If absent and the thread is routable, submit once and persist the acknowledgement.
Do not overclaim. The protocol calls clientUserMessageId unique and returns it for correlation. The public reference does not document duplicate submission as an idempotent no-op, so Impala must reconcile before retrying.

Minimum persisted outbox row

  • delivery_id -- unique locally.
  • server_identity, thread_id, client_message_id.
  • delegation_id, completion status, and callback text.
  • state -- pending, unknown, accepted, or consumed.
  • Optional accepted turn_id or queued-submission ID.
