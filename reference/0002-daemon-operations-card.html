Reference 0002

Daemon operations card

Commands, invariants, and recovery rules for an Impala-managed local app server.

Local topology

  • One Codex app-server daemon per CODEX_HOME.
  • Default socket: $CODEX_HOME/app-server-control/app-server-control.sock.
  • The socket directory is owner-only on Unix.
  • Each client connection performs its own initialize handshake.

Commands

daemon start

codex app-server daemon start
Idempotent; returns when the socket is ready for initialization.

--remote

codex --remote unix://
Connects the TUI to the default socket for its CODEX_HOME.

Explicit socket

codex --remote unix://PATH
Removes ambiguity when Impala has already resolved the socket.

Do not confuse

  • Codex app-server daemon: owns Codex threads and turns.
  • Impala PTY daemon: keeps terminal processes and buffers alive.
  • Remote TUI: a TUI connected to another app-server process; the socket may still be local.
  • Remote control: optional daemon exposure for remote clients; local Unix-socket use does not require treating it as the control plane.

Recovery sequence

  1. Detect transport loss; do not translate it into thread completion.
  2. Run idempotent daemon start if the managed daemon is unavailable.
  3. Reconnect and repeat initialize.
  4. Resume the stored threadId.
  5. Reconcile the returned thread state before sending new input.
Invariant. Impala, the TUI, and the callback client must resolve the same CODEX_HOME and socket. Otherwise they are controlling different app servers.
