One daemon, two clients

Your tangible win: trace the TUI and Impala to one control socket, then recover without confusing a lost connection with a lost conversation.

Starting point. You already know that the app server owns the thread and that Impala needs its threadId. This lesson locates that server and shows how both clients reach it.

The daemon is the shared owner

codex app-server daemon start starts the managed app server for the active CODEX_HOME. The command is idempotent and returns only after the server can answer an initialize handshake on its Unix control socket.

Both arrows terminate in the same daemon behind the socket. The clients do not connect to each other.

The word “remote” can be misleading here. codex --remote unix:// means the TUI uses an app server outside its own process. That server can still be on the same Mac through a private Unix socket.

CODEX_HOME selects the server

The default socket path is derived from CODEX_HOME, falling back to ~/.codex. If Impala starts a daemon with one home but launches the TUI with another, both sides can look healthy while controlling different servers.

Resolve once

Impala determines the effective Codex home before daemon startup or TUI launch.

Pass explicitly

The TUI and control client use the same absolute socket address.

Verify identity

Thread resume must succeed on that server before Impala submits completion input.

Connection state is not thread state

A disconnected TUI is a missing view. A disconnected Impala client is a missing controller. Neither fact alone proves that the thread completed, failed, or disappeared.

After transport loss, a client reconnects, performs initialize again, and resumes the stored threadId. It then reconciles returned state before sending new input. A daemon restart is more serious than a client reconnect, so Impala must not assume that in-flight tool execution survived it.

Two different daemons. Impala’s PTY daemon preserves terminal processes and scrollback. The Codex app-server daemon owns threads and turns. Keeping both may be correct; treating either one as the other is not.

Impala startup contract

  1. Resolve one effective CODEX_HOME and absolute control-socket path.
  2. Run idempotent daemon start and wait for readiness.
  3. Launch the TUI against that socket while retaining its PTY.
  4. Open and initialize Impala’s own connection only when it needs control access.
  5. Persist thread identity separately from pane and transport identity.
